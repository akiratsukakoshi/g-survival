# 第2章「壁の中」迷路化 設計書（2026-09-11、Fable起草）

ガクチョの実プレイ指摘（2026-09-11）を受けた再設計。実装は Opus に委譲し、Fable が検収する。
原仕様 §9 フェアネス規約と `docs/chapter2-spec.md` §4〜6 を上位とする。

## 0. ガクチョの指摘（原文の要旨）

1. ビジュアルの配置と実際の高低差が関係ない。台形（断熱材の山）と直方体（仕切り）以外は3Dの座標軸がない。
2. 壁のビジュアルが無いのに左右の移動限界になっている。
3. ゴールが分からない。壁面に穴があり、その先が台所、という想定にしたい。
4. このステージは迷路にしたい。壁面の中の迷路を下へ下へ、迷いながらルートを探す。細かく障害物を置いてルートを絞る。
5. 冒頭の仲間が散っていくシーンは不自然なので削除。

## 1. 設計原則（今回の憲法）

- **A. 見た目＝当たり判定。** プレイ面（壁板の表、z≥0）に描く立体はすべて迷路グリッド由来で、衝突か登坂の実体を持つ。実体を持たない装飾は描かないか、壁板面（z≤0）に沈める。現行の配管・横梁・断熱材の帯・横穴の枠のような「描くだけ」の物体は撤去する。
- **B. 境界は見える壁。** `LEFT=4 / RIGHT=28` のハードクランプを廃止し、グリッド外周の `#` セル（間柱の材木）が移動限界になる。
- **C. ゴールは壁の穴。** 最下段に壁板を貫く矩形の穴を開け、奥に台所の床と暖色の光を置く。光は離れた場所から壁に漏れ、非言語の導き（§9-5）になる。穴に入ると既存の「床板の軋み→スリッパの影→終幕」を再生する。
- **D. 手書きの迷路。** 乱数を使わず ASCII マップで固定する。下へ下へ蛇行し、行き止まり多数、単セルの障害物で通路を絞る。到達可能性は BFS で機械検証する。
- **E. 既存の核ルールは保つ。** 隙間幅と身体幅、ムカデの予告0.6秒→頭部接触のみ、ゲジ10秒周期、ヤモリの予告、章内脱皮（1.02→1.20）、章間セーブ、`chapter2Test` API。数値は AI 暫定値のまま。

## 2. グリッド仕様

- 1セル = 2.0 ユニット。横 14 列 × 縦 46 行。sim 座標は現行どおり x 右・y 下（world は `(x, -y, z)`）。列 c → x∈[2+2c, 4+2c]、行 r → y∈[2r, 2r+2]。プレイ域は x 2〜30、y 0〜92。
- 新モジュール **`src/chapter2-maze.ts`**（three.js に依存せず、`import.meta.env` も使わない。Node の `--experimental-strip-types` で読める純粋 TS）:
  - `MAP: string[]`（46行×14文字）と `CELL=2`
  - `parseMaze()` → セル配列、`start`、`goal`、`moltCell`、`centipedeColumn {x, yTop, yBottom}`、`gejiRow {y, xLeft, xRight}`、`geckoLair {x,y}`、`slits[]`（位置・向き・幅）
  - `blockedAt(x,y,r,who:'player'|'enemy', bodySize)`：円と矩形の重なりで判定。`#` は常時ブロック。隙間セルは「2本の柱（ジャム）」の矩形として扱い、**柱の実寸から通行可否が幾何的に決まる**（bodySize/2 の円が通るか）。敵には隙間セル・ポケットセルを全面ブロック。
  - `heightAt(x,y)`：`~` セルの山の高さ（現行 `heightAt` の台形ロジックを流用、頂上 1.2）。
  - `reachable(bodySize)`：4近傍 BFS。`1` 隙間は bodySize≤1.10、`2` は ≤1.40 の時だけ通る。最短経路（セル列）も返す。
  - `renderAscii(path?)`：検収用。経路を `*` で重ねた ASCII を返す。
- **凡例**

| 文字 | 意味 | 衝突 | 描画 |
|---|---|---|---|
| `#` | 間柱・木片（壁） | プレイヤー・敵とも不可 | 材木ボックス、高さ `WALL_H=1.6`（暫定）。行方向の連続セルは1メッシュに結合 |
| `.` | 通路 | — | 壁板の表（描かない） |
| `~` | 登れる断熱材の山 | 高さあり（乗れる） | 現行の台形メッシュ。頂上 1.2。高さ≥.3 なら地表の敵の接触を受けない（現行ルール） |
| `1` | 細い隙間、幅 1.10 | 3齢(1.02)は通る、4齢(1.20)は通らない。敵は不可 | 2本の柱を残しスリットを開ける（スリットの軸は通路側の隣接に合わせる） |
| `2` | 広い隙間、幅 1.40 | どちらの齢も通る。敵は不可（退避口） | 同上 |
| `o` | 退避ポケット | 敵は不可 | 壁板をやや窪ませた袋（voidMat）。中に居れば `sheltered()`＝チェックポイント |
| `M` | 脱皮ポケット | `o` と同じ | `o` と同じ見た目＋Space 3秒で脱皮（現行ロジック） |
| `S` | スタート | 通路 | — |
| `G` | ゴールの穴 | 通路。中心に入ると終幕シーケンス開始 | 壁板を貫く穴（`THREE.Shape` の hole で壁板を作る）、奥に床と暖色ポイントライト |
| `c` | ムカデ巡回列 | 通路 | ムカデは列の上端〜下端を往復（既存の sin 巡回を範囲に合わせる） |
| `g` | ゲジ横断行 | 通路 | 既存の 10秒周期・0.9秒予告→横断。行の x 範囲を横切る |
| `y` | ヤモリの巣 | 通路 | ヤモリはここに潜む。検知帯＝巣から半径 6（暫定）で遮蔽なし |

- 隙間の「ねじ込み」: 通れる幅の隙間に柱ごしに押し込むと、垂直方向の座標をスリット中心へ step 以内で寄せる（漏斗）。通れない幅では止まり、現行の「胸が擦れる。ここはもう通れない。」を出す。左長押しの触角プローブは現行文言を流用。
- プレイヤー衝突半径は `bodySize/2`。通路幅 2.0 に対し余裕 0.8〜1.0。

## 3. 迷路の巨視構造（Opus が ASCII を起草。以下は必須条件）

| 行 | 区画（HUD の objective 文言は現行のまま y で切替） | 必須要素 |
|---|---|---|
| 0〜7 | 断熱材の層 | `S` は上段中央付近。`~` 2〜3個。分岐で迷わせ始める |
| 8〜19 | 配線と間柱のシャフト | `c` 列（長さ 6〜9 セル）。列の両脇に `2` 隙間＋`o` ポケットを少なくとも 2つ（走って逃げ込める距離＝5セル以内） |
| 20〜30 | 湿った配管の分岐 | `g` 行（幅 5〜8 セル）。行の中か直前に `~` か `o` の退避。**`M` 脱皮ポケット**はこの区画の後半 |
| 31〜40 | 巾木の裏 | `y` の巣。巣の帯を抜ける 2 経路のうち 1 つは `1` 隙間（脱皮後は使えない誘惑）、もう 1 つは `2` |
| 41〜45 | 床下 | `G` は最下段の**右寄り**。穴の直前で通路を 1 本に絞る |

- **到達性**: BFS で (a) 1.02 で S→G、(b) 1.20 で S→G（`1` を使わない）、(c) 1.02 で S→M、(d) 1.20 で M→G がすべて真。
- **迷路らしさ**: 行き止まり（通路セルで通路隣接が 1 つ。S/G/o/M を除く）を **8 個以上**。最短経路長（1.02）を **110 セル以上**（縦 46 セルの 2.4 倍）。
- **公平性**: `1` 隙間は M より前に最低 1 つ「近道」として置く（脱皮前だけ使える）。`c`・`g`・`y` の帯に、予告時間内に届く退避（`o` / `~` / `2`）を置く。即死経路を作らない。
- ASCII は外周をすべて `#` にする。

## 4. `src/chapter2.ts` の変更点

- 削除: `gaps`、`terrain`、`LEFT/RIGHT`、`blocked/heightAt/clearLine` のローカル版、配管 `pipeAt`・横梁・断熱材の帯・横穴の枠・`wind` バー、**`companions` と散開描画**。
- 追加: 迷路モジュールからの壁・山・隙間・ポケット・穴の描画。壁板は `ShapeGeometry`+`ExtrudeGeometry`（G の穴つき）。穴の奥に台所床（明るいタイル色の平面、z≈-1.6）と `kitchenLight`（暖色、距離 9〜10、穴から壁へ漏れる）。
- ゴール: プレイヤー中心が G セル内 → `humanTimer` 開始（現行の軋み→スリッパ→`finish(true)`）。終幕中は主人公を穴へ沈める（z を 0.72→-0.8 へ 1.2 秒、暫定）。
- 敵: ムカデ巡回範囲・ゲジ行・ヤモリ巣を迷路データから取る。追跡は現行の直進＋`blockedAt(enemy)` で壁に止まる。**視線が 1.0 秒以上切れたら `recover`**（壁に張り付いて押し続ける状態を作らない）。ヤモリの突進も壁で止まる。
- `sheltered()`＝ポケット内か隙間セル内。チェックポイントは現行どおり `sheltered()` で更新、初期値は S。
- カメラ・ランプ: 現行の斜め追従を維持。ランプ距離 18→14、霧 .025→.03（暫定。迷いを作るため視界を少し詰める）。プレイヤーが壁に隠れないこと。
- `chapter2Test` に `route()`（現 bodySize の BFS 経路をセル中心座標列で返す）と `maze`（cell, cols, rows, start, goal）を追加。既存の `step/setPosition/snapshot/setEnemy/startMolt` は維持。

## 5. 検証

- 新規 `chapter2-maze-check.mjs`（Node のみ、ブラウザー不要）: §3 の到達性 4 条件・行き止まり数・最短経路長・凡例の個数（S=1, G=1, M=1, c≥1, g≥1, y≥1）を assert し、`renderAscii(path)` を標準出力に出す。`scripts/verify.sh` の非ブラウザー部に追加。
- `chapter2-route-audit.mjs`: `chapter2Test.route()` の経路をキー入力で走破し、終幕到達・生存 ≥7/8（自然経路で喪失は最大 1）・例外 0 を assert。到達途中と終幕のスクリーンショットを `artifacts/` に残す。
- `chapter2-audit.mjs`: 座標を迷路データから取るよう更新（隙間退避、狭い隙間の拒否、ムカデ予告・追跡・退避・喪失、ヤモリ予告、脱皮の保存、終幕、13匹引継ぎ）。
- 自動検証で判定できないもの（迷う楽しさ、初見 8〜10 分、恐怖感、実機 FPS、穴の分かりやすさ）は map.md にガクチョ判定待ちとして残す。
