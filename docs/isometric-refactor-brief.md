# 斜俯瞰3Dリファクタ 指示書 — g-survival

## ゴール

3DアクションファンタジーRPGのような**大胆な斜俯瞰視点**。かつ、床だけでなく**壁も垂直に登れる**。
プレイヤーはクロゴキブリの1齢幼虫。ホラー寄りのトーンは維持する。

---

## 現状の構造（変更前）

| 項目 | 現状 |
|---|---|
| カメラ | `OrthographicCamera(-14,14,8,-8,.1,100)` を `position(9,5,30)` → `lookAt(9,5,0)`。真正面からの平行投影 |
| 世界 | X-Y平面に建てた「壁の断面」。Zは薄い奥行き（障害物 depth 1.6、背景壁は z=-3.5 に1枚） |
| 座標 | `simulation.ts` は全て `{x,y}` の2次元。`go()` で `clamp(x,0,100)` / `clamp(y,1,8)` |
| 衝突 | `OBSTACLES` は X-Y の矩形リスト |
| 暗闇 | `main.ts` の `#veil` キャンバスに**スクリーン空間の2D**で描画。`project()` でワールド→スクリーン、`reach()` で X-Y 平面のレイキャスト |
| 生物の向き | `animals.ts` の `animateAnimal` が `g.rotation.z = heading` のみで決定 |

つまり、既に3Dで描画されているが、**カメラの置き方と世界の組み方が2D前提**になっている。

---

## 変更後の設計方針

### 1. 座標系

- ワールドを「**床面 = X-Z、高さ = Y**」に組み直す（Three.js標準）
- `simulation.ts` の Point を3次元に拡張する
- 移動は「**接触面上の2Dパラメータ空間**」で考えるのが安全。プレイヤーは常に何らかの面（床・壁・天井）に貼り付いており、`面の法線` と `面上の位置` を持つ。自由な3D移動として実装すると壁登りが破綻する

### 2. 壁登り

- 各コリジョン面に**法線**を持たせる。プレイヤーの姿勢は接触面の法線から決まる
- 面から面への遷移（床→壁）は、進行方向にレイを飛ばして次の面を検出し、法線を補間して乗り移る
- ゴキブリの「上下」は常に接触面の法線。**カメラは回さない**。プレイヤーだけが回る。天井に貼り付いても画面は回転しない
- スタミナ消費・落下・滑落は後回しでよい

### 3. カメラ

- `PerspectiveCamera`（fov 40〜50）に変更する。大胆な斜俯瞰は平行投影より透視投影のほうが効く
- 俯角 35〜50度、方位角 45度前後から見下ろす（アイソメトリック風）
- プレイヤーを追従。ゴキブリは速いので、位置は `lerp` で減衰させないと酔う
- ズーム倍率をプレイヤーの状態（脱皮中など）で変えられるようにしておくと演出に使える

### 4. 暗闇（最大の注意点）

現在の `#veil` はスクリーン空間の2D合成で、X-Y平面前提の `reach()` に依存している。**カメラを傾けた瞬間に破綻する。**

選択肢は2つ。**どちらを採るか先に決めてから着手すること。**

- **(a) スクリーン空間のまま維持** — `project()` でワールド→スクリーンに落とすので原理的には動く。ただし扇形のレイキャストを3D対応に書き直す必要がある。安上がりだが、傾いた床に光が正しく乗らない
- **(b) 3Dライティングに移行** — プレイヤーに `SpotLight` を持たせ、`fog` を濃くして視界を作る。表現力は上がるが影の計算が増える

**初手は (a) で通し、絵が固まってから (b) を検討する**のを勧める。

### 5. 世界の作り直し

- `OBSTACLES` は矩形リストのままでは足りない。床・壁・天井を持つボックス配列に拡張し、それぞれの面を歩けるようにする
- 屋根裏という舞台設定は維持。梁・断熱材・配線という要素も維持
- 100 unit の一本道 → 斜俯瞰なら奥行き方向にも広がりを持たせられる。ただし**第1章のゲーム目標（餌と水を探して安全な隙間へ、満腹で脱皮）は変えないこと**

## 触ってはいけないもの

> **`src/animals.ts` は編集しないこと。**
> 別作業で Blender 製の3Dモデル（.glb）に差し替え中。以下のインターフェースだけ守れば衝突しない。

**現在:**

```ts
export function createAnimal(kind:'roach'|'spider'|'ant', scale=1): THREE.Group
export function animateAnimal(g:THREE.Group, time:number, speed:number, heading:number, molt=0): void
```

**差し替え後（予定）:**

```ts
export async function loadAnimals(): Promise<void>   // 新規。scene構築前に一度 await する
export function createAnimal(kind:'roach'|'spider'|'ant', scale=1): THREE.Group   // 同じ
export function animateAnimal(g:THREE.Group, time:number, speed:number, orientation:THREE.Quaternion, molt=0): void
```

変更点:

- `heading:number` → `orientation:THREE.Quaternion`。**壁に貼り付く姿勢は1軸の回転では表せないため**
- モデルのローカル軸を glTF 標準に揃える: **-Z が前方、+Y が上（背中側）**。現在の `animals.ts` は「+Xが前方、+Zが上」なので変わる
- `.glb` のロードが非同期なので、`loadAnimals()` を `await` してから scene を組む形になる

呼び出し側（`main.ts`）は新シグネチャに備えておくこと。実装が届くまでは、現行の `heading` から

```ts
new THREE.Quaternion().setFromEuler(new THREE.Euler(0, heading, 0))
```

を作って渡すアダプタを置いておけばよい。

## 進め方（フェーズを守ること）

1. まず**カメラだけ**傾けて現状を描画し、スクリーンショットを撮る。壁が書き割りに見える度合いを目視で確認する
2. 世界のジオメトリを床面ベースに組み直す。この段階ではプレイヤーは床だけ歩ければよい
3. 壁登りを入れる
4. 暗闇の演出を新しい視点に合わせて作り直す
5. アリ・クモのAIを3D経路に対応させる

各フェーズごとにコミットし、スクリーンショットを `artifacts/` に残すこと。

## 実行環境の制約

- **Intel Iris Xe 内蔵GPU**（Core i7-1195G7 / 4コア8スレッド / RAM 32GB）。専用VRAMなし
- 影とライトを増やしすぎるとフレームレートが落ちる。**フェーズごとにFPSを計測すること**
- 群れのゴキブリ12匹＋アリ28匹＋クモ2匹が同時に描画される前提で予算を組む
- 操作はキーボード＋マウス
- トーンはホラー寄り。人間は足元・影・手だけ描き、顔は見せない
